# Contract: localization package `packages/i18n`

Shared by the server (SSR, API messages, emails, CSV) and the SPA. Decision record: research R25.

## Public files (no barrel; each file is an `exports` entry)

| File | Exports |
|---|---|
| `locales.ts` | imports `LOCALES` / `Locale` from `@learnly/contracts/enums` (single source), exports `DEFAULT_LOCALE = 'uk'`, `isLocale(x)`, `negotiateAcceptLanguage(header): Locale \| null`, `resolveLocale({ query, cookie, user, acceptLanguage }): Locale` |
| `messages/uk.ts` | `uk` dictionary object (`as const`), `type Messages = DeepStringShape<typeof uk>` |
| `messages/en.ts` | `en` dictionary `satisfies Messages` |
| `keys.ts` | `type MessageKey` = union of dotted paths of `Messages`, `type MessageParams<K>` derived from placeholders |
| `translator.ts` | `createTranslator(locale, dict, { onMissing? }) → t<K extends MessageKey>(key, params?) => string` |
| `format.ts` | `formatDate(locale, date, style)`, `formatNumber(locale, n)`, `formatPercent(locale, n)`, `formatDuration(locale, minutes)`, `formatRelative(locale, date, now)` |
| `zod.ts` | `zodErrorMap(locale)` (wraps `z.locales.uk()` / `z.locales.en()`), `localizeIssues(issues, t) → { path, message }[]` |

## Dictionary layout

Namespaces (top-level keys, same in both locales):

| Namespace | Content |
|---|---|
| `common` | buttons, generic labels, pagination, empty/error states, plural units |
| `site` | public pages, header, footer, catalog, course page, auth pages, certificate page; static pages as `site.pages.<page>.title` + Markdown `site.pages.<page>.body`, FAQ as `site.pages.faq.items[]` |
| `admin` | admin panel pages, actions, `audit.<action>` labels for every `AuditAction` |
| `app` | SPA screens (dashboard, player, quizzes, notes, teach, settings, profile) |
| `notifications` | one entry per `NotificationType`, with payload placeholders |
| `emails` | `<template>.subject` and every text used by `views/emails/<template>.ejs` (one template per email, no per-locale templates) |
| `errors` | one entry per `ErrorCode` and per domain error key (e.g. `errors.enrollment.certificateIssued`) |
| `validation` | custom rule messages (`validation.password.letterAndDigit`, `validation.text.min`, ...) |
| `enums` | labels for every enum value (`enums.courseLevel.beginner`, `enums.locale.en`, ...) |
| `readiness` | BR-P1 checklist item labels keyed by `unmet` keys |

## Message syntax

- Interpolation: `"Hello, {name}"`.
- Plurals (ICU-lite): `"{count, plural, one {# lesson} few {# lessons} many {# lessons} other {# lessons}}"`;
  categories resolved with `new Intl.PluralRules(locale)`; `#` is replaced with the formatted number.
  Ukrainian messages provide `one`, `few`, `many`, `other`; English ones `one`, `other`.
- No HTML in messages; rich text is composed in templates/components.

## Rules enforced by tests

1. Both dictionaries have the same key set (no missing, no extra keys).
2. For every key, the set of `{placeholders}` and the presence of `plural` are identical in both
   locales.
3. Every Ukrainian plural message defines `one`, `few`, `many`, `other`; every English one defines
   `one`, `other`.
4. Every `ErrorCode`, `NotificationType`, `AuditAction`, enum value and readiness item has a message
   (checked by iterating the enums from `packages/contracts`), and every static page has a title and
   a body.
5. No empty strings.

## Typed keys in server APIs

`AppError`, the mailer subject, flash messages and CSV column headers accept only `MessageKey`
values, so a hard-coded sentence cannot be passed to them (SC-011). JSX and EJS are covered by the
lint rule and `scripts/check-ejs-strings.mjs`.

## Locale resolution (`resolveLocale`)

Order: valid `query` (`?lang`) → valid `cookie` → `user.locale` → `negotiateAcceptLanguage(header)`
(first supported primary subtag by q-value) → `DEFAULT_LOCALE`. Pure function, 100 % tested, used
by both the server and the SPA (the SPA passes `navigator.languages` and `Me.locale`).

The `locale` cookie stores only an explicit choice (`?lang`, `POST /locale`, the SPA switcher). On
every successful login the server sets it to the account's `locale`, so a device opens in the
account language after login.
